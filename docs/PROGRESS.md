### أ) أساس الاستخدام أصبح مرناً بدل نص حر إلزامي

| قبل | بعد |

- **ما لم يتغيّر:** القيمة النهائية تُسجَّل دائماً في `metadata.json` مهما كان الوضع — المبدأ 4 محفوظ، والاحتكاك أُزيل.
- الاختبارات: `tests/test_licensing.py` (24 اختباراً).

### ب) معالجة تعقيد الاستخدام

| المشكلة المرصودة | الحل المنفَّذ |
|---|---|
| «ما هو الأمر الأساسي؟» | `ar-clipper quickstart` — 3 أسئلة وينتج مقطعاً |
| «أقل مجموعة خيارات ناجحة؟» | `--preset` — 6 مسارات جاهزة مُختبَرة |
| «لا مسار واضح لحالتي» | `ar-clipper presets` — جدول «إذا أردت X استخدم Y» |

### 3.2 نقاط الارتكاز الجاهزة من المرحلة 1

البنية الحالية تجعل المرحلة 2 إضافة نظيفة لا إعادة كتابة:

- `Segment.speaker` **موجود مسبقاً** في المخطط → وحدة Diarization تملؤه فقط.
- `run_pipeline()` تقبل **قائمة** `ClipRequest` → محطة التحليل تولّد القائمة وتمرّرها كما هي.
- `ClipRequest.title` موجود → وحدة توليد المحتوى تملؤه.
- `Transcript.full_text` جاهز → يُرسَل مباشرةً كـ Prompt للـ LLM.
- `--no-translate` وتخزين الترانسكربت يسمحان بتجربة التحليل بسرعة دون إعادة تفريغ.

### 3.3 الخطوة الأولى المقترحة

1. تثبيت Ollama محلياً + نموذج (Llama 3 8B أو Qwen2 7B).
2. إنشاء `core/analyze/llm_client.py` بواجهة مجرّدة (مثل `BaseTranslator`) لتسهيل تبديل النماذج.
3. بناء Prompt يُرجع JSON صارماً: `[{start, end, type, reason, score}]`.
4. أمر CLI جديد: `ar-clipper suggest <المصدر>` يعرض المقترحات قبل الإنتاج.

## 7. المرحلة 6: التوسّع إلى SaaS — ⏸️ مؤجَّلة عن قصد

خارج نطاق التنفيذ الحالي بالكامل حسب الوثيقة الأم (القسم 11).

**ما يحميه التصميم الحالي:**
- المنطق الأساسي (`core/`) لا يستورد أي شيء من `cli/` → فصل كامل يسمح بإضافة FastAPI لاحقاً.
- كل الإعدادات تُقرأ عبر `Settings` وتقبل التجاوز بمتغيرات البيئة → جاهزة للحاويات (Containers).
- المسارات كلها نسبية لجذر المشروع وقابلة لإعادة التوجيه لكل مستخدم → يمهّد للـ Multi-tenant.
